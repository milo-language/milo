# Gate: bun scripts/leak-check.ts --check

# NOT on this list, and why (2026-08-21): resultMap. Its remaining leak is NOT the closure
# environment this commit fixed and not the ok-payload the previous one fixed — it is the
# Err payload of a DISCARDED temporary:
#
#   print(err3.map((n) => n * 10).unwrapOr(0))   // "boom-nope" is never freed
#
# unwrapOr reads one variant's payload out of the receiver and nothing drops the other,
# which for a receiver that is itself a temporary leaves the Err string owned by nobody.
# Re-add it in the same commit that drops the unconsumed payload of a temporary receiver.
#
# Before trusting either number: the two optimization levels have DIFFERENT blind spots and
# neither is sound alone. This gate builds at the default -O2, which elides allocations
# nothing observes; -O0 leaves stale pointers in stack slots, which keeps a leaked block
# reachable so `leaks` stays quiet. resultMap shows both sides: it leaks at -O2, not at -O0.
