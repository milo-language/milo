# Raw descriptors out of the safe std API (2026-10)

Item 2 of "Fd ownership, finished" in [stdlib-next-2026-10.md](stdlib-next-2026-10.md).
A descriptor is an `i32`, and an `i32` is Copy, so a number outlives the handle that
owns it and then names whatever the kernel reused it for. Discipline does not scale; the
rule is now a compile error: **a pub std fn or method that takes or returns a bare
descriptor is `@unsafe`, or takes a handle, or is gone.** Migration for users is in
[breaking-changes.md](../breaking-changes.md).

## Mechanism

- `@unsafe` now applies to methods (static and instance, inherent and trait impls); the
  checker resolves the call to its mangled symbol and asks for `unsafe` there
  (`requireUnsafeMethod` in src/checker.ts). Before this, only free fns could carry it,
  which is why the descriptor accessors had to stay safe.
- `trait AsFd { fn rawFd(self: &Self): i32 }` (std/io) is how a call borrows a
  descriptor: `Select.onRead<T: AsFd>(h: &T)` gets the number only for the duration of a
  borrow the checker enforces. Every std impl of `rawFd` is `@unsafe`. Implemented by
  `File`, `OwnedFd`, `FdStream`, `TcpStream`, `TcpListener`, `UnixStream`,
  `UnixListener`, `WsConn`, `Pty`, `SignalPipe` and the stdio handles `Stdin {}`,
  `Stdout {}`, `Stderr {}` (process-lifetime, so lending them is always valid).
- A generic bound violation now carries the call site's span, so `sel.onRead(0)` points
  at the caller rather than into std/select.milo.
- Owning types keep their descriptor in a `_`-private field, so no other file can build
  one around a number (which its Drop would then close) or read it.

## Gate

`tests/rawFdApi.test.ts` parses every `std/*.milo` (platform arms included) and fails on
a pub fn, a method of a pub type, or a public field of a pub struct whose parameter,
return or field is an integer named like a descriptor (`fd`, `fooFd`, `sock`,
`wakeupId`, `rawFd`, `take`, `sysOpen`, ...) unless it is `@unsafe` or in `ALLOWED`. It
also pins sentinel names the scan must keep recognising (so a regex drift cannot turn it
into "0 found"), rejects stale `ALLOWED` entries, and runs a synthetic file through the
detector. Shown failing: a temporary `pub fn closeLater(fd: i32): i32` appended to
std/fs.milo turned it red with `std/fs.milo: closeLater`; removing it turned it green.

## Inventory

The starting list was every pub std fn whose signature names a descriptor (`milo api
--json` plus a source read for fields, `take` and the wakeup ids): the "~69" of the
friction analysis, counted per name rather than per platform arm. Counts per name; an
API present on several arms counts once.

### Converted to a handle (17)

| was | now |
|---|---|
| `Select.onRead(fd)`, `Select.onWrite(fd)` | `<T: AsFd>(h: &T)` |
| `waitReadable(fd, d)`, `waitWritable(fd, d)` (std/timer) | `<T: AsFd>(h: &T, d)` |
| `OwnedFd.dup(fd)` | `OwnedFd.dup<T: AsFd>(h: &T)` |
| `fdIsTerminal(fd)` (std/pty, 3 arms) | `isTerminal<T: AsFd>(h: &T)` |
| `installSignalPipe(sig): i32` | `Result<SignalPipe, string>`; `SignalPipe` owns both pipe ends and uninstalls on drop |
| `drainSignalFd(fd)` | `SignalPipe.drain(): bool` |
| `wsAccept(fd, raw)` | `wsAccept(conn: TcpStream, raw)` (consumes) |
| `TlsStream.fromFd(fd, ...)` | new safe `TlsStream.fromTcp(conn: TcpStream, ...)`; `fromFd` kept `@unsafe` |
| `Log.setSinkFd(fd)` | `setSinkFd(fd: OwnedFd)` (consumes) + `setSinkStdout()` / `setSinkStderr()` |
| `mmapFile(fd, size)` | `mmapFile(f: &File, size)` |
| `syncFd`, `dataSyncFd`, `setFdMode`, `setFdOwner`, `truncateFd` (std/fs, unused anywhere but kept as features) | `syncFile`, `dataSyncFile`, `setFileMode`, `setFileOwner`, `truncateOpenFile` over `&File` |

Also new: `TcpStream.close()` and `UnixStream.close()`, which replace the
`close(s.take())` idiom every caller of `take` used.

### Kept raw, `@unsafe` (79 names)

Each is a primitive the owning types are built from, a raw constructor, or a raw
accessor. Callers in std vouch inside `unsafe` that they still own the number.

| module | names | why raw |
|---|---|---|
| std/os | `sysRead`, `sysWrite`, `sysOpen`, `sysDup`, `sysIsatty`, `sysClose`, `sysLseek`, `sysSocket`, `sysListen`, `sysAccept`, `readFd`, `writeFd`, `recvFd`, `sendFd`, `acceptFd`, `acceptFdNb`, `bindIn`, `bindIn6`, `bindUn`, `connectFdIn`, `connectFdIn6`, `connectFdUn`, `getSockPort` (23) | the replay-aware, green-aware syscall layer under File/TcpStream/Child |

| std/event (3 arms) | `setNonblocking`, `clearNonblocking`, `eventRegisterRead`, `eventRegisterWrite`, `eventDeregister`, `eventLoopFd`, `eventLoopFromFd`, `eventLoopInitWakeup`, `eventLoopNotify`, `eventLoopDrainWakeup`, `eventLoopCloseWakeup` (11) | the scheduler's poller; the wakeup id is an eventfd on Linux |

| ownership hand-off | `TcpStream.take`, `UnixStream.take`, `WsConn.view`, `TlsStream.fromFd` (4) | the caller takes over (or vouches for) the number's lifetime |

### Made private (4 fns, 1 type, the descriptor fields)

- `connectFd`, `sysRecv`, `sysSend` (std/os), `replayFdSynthetic` (std/replay): only their
  own file called them.
- `Socket` (std/http): its field is a bare fd and only `serve` uses it.
- Fields renamed `_`: `File.fd`, `FdStream.fd`/`socket`, `TcpStream.fd`,
  `TcpListener.fd`, `UnixStream.fd`, `UnixListener.fd`, `TlsConn.fd`, `TlsListener.fd`,
  `TlsStream.fd`, `WsConn.fd`, `Pty.masterFd` (3 arms), `EventLoop.kqfd`/`epfd`/`slot`.
  Two fixtures and an example read `listener.fd` directly, which the old public field
  allowed.
- `FdReader` became a struct with private fields instead of an enum whose variants
  (`FdReader.Green(fd)`) built one around any number.
- New raw helpers went in as file-private free fns, not methods, because a method is as
  public as its type: `armFd` (std/select), `logSetSink` (std/log).

### Deleted (3 unused, plus 2 replaced)

`connectIn`, `connectIn6`, `connectUn` (std/os): no caller in std, tests, examples,
milojs, dapweb or the sibling packages; `connectFdIn*` are the green-aware spellings.
`drainSignalFd` and `fdIsTerminal`, replaced as above.

### Allowed safe (the gate's `ALLOWED`, 6)

| name | reason |
|---|---|
| `fdReaderAttach` | the published `milo-json-rpc@v0.1.0`, which `examples/tools/java-dap` builds against, calls it outside `unsafe`. It only reads and never closes. Becomes `@unsafe` once a milo-json-rpc release reads frames through a handle |
| `nodeFd`, `sElFd`, `tWaitFd`, `sSelFdHead` (std/runtime) | byte offsets into the scheduler's record layouts, not descriptors |
| `EpollEvent.dataFd` (std/platform.linux) | the `epoll_event` layout mirror std/event.linux fills in from another file; plain data, inert until passed to an `@unsafe` call |

### Not descriptors (false positives of the first grep)

`efdCloexec`/`efdNonblock` (flag constants), `wlSockIdx`/`wlMaskIdx` (table indices),
`solSocket`, `sockAddrUnMaxPath`, `selectRegisterFd`/`selectUnregisterFd` (take a node
pointer), `WsConn.tlsHandle` (an SSL pointer), `getConsoleModeOf`/`stdinHandle` (Win32
console HANDLEs the process never closes).

## Out of scope, noted

- `pub extern fn` declarations (`close`, `dup`, `dup2`, `isatty`, `fcntl`, ...) are
  governed by the extern-call rule, not this gate: a scalar-only extern call outside
  `unsafe` is the `extern-call` warning (`--deny=extern-call` makes it an error).
- View types still copy the number out of a borrow (`File.stream()` → `FdStream`,
  `fdReaderAttach`): the view can outlive its owner. That is the documented sharp edge of
  the streams API; closing it needs views the checker ties to the owner.
- `milo-json-rpc` (`readFrame(fd: i32)`) and `postgres` (`TlsStream.fromFd`) are sibling
  packages with their own raw-fd APIs; postgres now needs `unsafe` around `fromFd` (or
  `fromTcp`).
