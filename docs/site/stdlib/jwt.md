# std/jwt

JSON Web Tokens (RFC 7519 / 7515) over HMAC-SHA2, pure Milo on [`std/hmac`](hmac), `std/base64`, `std/json` and [`std/subtle`](subtle). HS256/384/512 are deterministic, so a token produced here is byte-identical to PyJWT / jsonwebtoken for the same header, payload, and secret.

```milo
from "std/jwt" import { Jwt, JwtAlg, JwtVerifier, JwtError, jwtErrorMessage }
```

Verification returns the **claims**, not a bool. A yes/no verifier invites `if verify(token, secret) { ... }`, which happily accepts a token that expired three years ago or was minted for a different audience — the signature is only half the check. `Result<JwtClaims, JwtError>` makes "the signature is good" and "this token is valid right now" the same line of code.

Three attacks are handled explicitly:

- **`alg: none`** — the header algorithm must equal the one the caller asked for, so an unsigned token is `UnsupportedAlg("none")`.
- **Algorithm confusion** — the algorithm comes from the verifier, never from the token.
- **Signature timing** — the MAC comparison is `constantTimeEq` over raw bytes, and a non-canonical base64url signature is rejected rather than silently accepted.

HMAC algorithms only. RS\*/ES\*/PS\* need public-key crypto the standard library does not have; such a token is rejected as unsupported rather than downgraded.

## Signing and verifying

`Jwt.signHS256` signs a JSON payload string and returns a compact JWS:
`base64url(header).base64url(payload).base64url(HMAC)`. `Jwt.verifyHS256` checks the
algorithm, the signature, and `exp`/`nbf`/`iat` against the system clock with
`JWT_DEFAULT_LEEWAY` (60 s) of tolerance, then returns the claims.

```milo
match Jwt.verifyHS256(token, secret) {
    Result.Ok(claims) => {
        match claims.subject() {
            Option.Some(sub) => { print("hello " + sub) }
            Option.None => { print("anonymous token") }
        }
    }
    Result.Err(e) => { print(jwtErrorMessage(e)) }
}
```

## One policy, reused

`JwtVerifier` holds the policy in one place: which algorithm, how much clock skew,
which audience and issuer, and whether a token without `exp` is acceptable. `at` pins
the clock to a fixed instant, which is what makes a claim test reproducible.

```milo
let verifier = JwtVerifier.new(JwtAlg.HS256, secret)
    .audience("api.example")
    .issuer("auth.example")
    .requireExpiry()
let claims = verifier.verify(token)?
```

A rejection is a `JwtError` variant, not a `false`: the caller recovers differently from
`Expired` than from `BadSignature`. `jwtErrorMessage(err)` renders any of them as one
log-safe line.

### `JwtError`

```milo
pub enum JwtError
```

Why a token was rejected. Callers genuinely recover differently: `Expired` means
"refresh and retry", `BadSignature` means "this is an attack or the wrong key",
`WrongAudience` means "this token is for another service" — collapsing them into
`false` throws away the only information the caller needs.

Variants:

- `Malformed(string)`: Not three base64url segments, or a segment is not valid base64url / JSON.
- `UnsupportedAlg(string)`: The header's `alg` is not the one the verifier requires. Carries the value found in the token, so "none" shows up in the log verbatim.
- `UnsupportedCritical`: The header carries a `crit` extension this implementation does not understand (RFC 7515 §4.1.11 requires rejection rather than ignoring it).
- `BadSignature`: The MAC did not match. No detail: there is nothing safe to report.
- `Expired(i64)`: `exp` has passed. Carries the expiry, in seconds since the Unix epoch.
- `NotYetValid(i64)`: `nbf` is in the future. Carries the not-before time.
- `IssuedInFuture(i64)`: `iat` is in the future — the issuer's clock is wrong or the token is forged.
- `MissingClaim(string)`: A required claim (`exp`, or the `aud`/`iss` the verifier demands) is absent.
- `WrongAudience(string)`: `aud` is present but does not contain the audience the verifier requires.
- `WrongIssuer(string)`: `iss` is present but is not the issuer the verifier requires.

### `JwtVerifier`

```milo
pub struct JwtVerifier
```

A configured verifier: the algorithm and secret to require, plus which claims to
insist on. Build one with `JwtVerifier.new`, chain the options you need, and call
`verify`. Reusing a verifier is the point — the policy lives in one place instead
of being re-spelled at every call site.

Fields:

- `secret: string`
- `alg: JwtAlg`
- `leewaySecs: i64`
- `nowSecs: i64`: Seconds since the epoch, or -1 to read the system clock at verify time. A fixed value makes claim validation deterministic in tests.
- `audience: string`: "" means "do not check". An empty audience or issuer is not meaningful, so there is no ambiguity between "unset" and "must equal the empty string".
- `issuer: string`
- `requireExp: bool`
