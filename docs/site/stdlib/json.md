# std/json

Strict RFC 8259 JSON: a parser with typed accessors, a cursor API that navigates without
allocating, and builders (`Json.obj()`, `Json.arr()`) for writing. `Json.parseJsonc`
accepts comments and trailing commas.

```milo
from "std/json" import { Json }
```

## Example

```milo
from "std/json" import { Json }

fn main() {
    let doc = Json.parse("{\"name\": \"milo\", \"tags\": [\"fast\", \"safe\"], \"meta\": {\"stars\": 9}}")!

    print(doc["name"].str() ?? "unknown")         // milo
    print(doc["tags"][1].str() ?? "")             // safe
    print(doc["meta"]["stars"].i64() ?? 0)        // 9
    print(doc["missing"]["deeper"].exists())      // false

    for tag in doc["tags"].items() {
        print(doc[tag].str() ?? "")
    }

    // {...meta, stars: 10, lang: "milo"}
    let out = Json.obj().spread(doc, doc.curPath("meta")).int("stars", 10).str("lang", "milo").build()
    print(out)                                    // {"stars":10,"lang":"milo"}
}
```

`doc["a"][0]["b"]` indexes with a string key, an integer position, or a `JsonCur`, and
ends in a read: `.str()`, `.f64()`, `.i64()`, `.bool()`, `.len()`, `.exists()`,
`.raw()`, `.json()`, `.items()`, `.keys()`. A missing step is not an error; every read
after it is `None` (or empty), so `?? default` finishes the walk. It compiles to the
cursor methods below with no allocation per step. A step stored in a variable is a
`JsonCur`, which is only a position: a struct cannot hold the `&Json` it points into, so
it is read back through the document as `doc[cur]["field"]`. The chain must start at a
`Json` held in a variable or field.

The owned accessors (`get`, `at`) return a subtree as its own `Json`, a deep clone per
call. That reads well and is fine for configuration-sized input; on a large document
navigated in a loop, use indexing or the cursor methods (`curRoot`, `curField`,
`curChild`, `curStr`, `strAt`, ...) instead.

#### `Json.curRoot`

```milo
fn Json.curRoot(self: &Json): i64
```


`get`/`at` above return an owned Json by deep-cloning the whole document
(source string + every node) per call — navigating a large doc thousands
of times blows up to gigabytes. The cursor API instead hands out an `i64`
cursor into THIS document: navigation returns cursors (-1 = missing) with
zero allocation, and only leaf-string reads materialize (just that one
string). Start at `curRoot()` and chain:
  let user = doc.curField(doc.curChild(doc.curRoot(), 0), "name")
  match doc.curStr(user) { Some(s) => ..., None => ... }

A cursor is not a bare node index: the document's brand rides in its
high bits (see jsonCurResolve above). Resolving a cursor against a
different Json used to read a wrong-but-in-bounds node of the other
document and report nothing; now it aborts, naming the mistake. -1 still
flows through every accessor as "nothing here", so navigation stays
total for any in-document miss. A memberwise copy of a Json shares its
brand, which is sound because copying preserves node numbering; the
documents `get`/`at`/`path` return carry a fresh brand because
extraction renumbers the pool.

This is one of two ways to reach a nested value. The other is to chain the
owned accessors with `Option.andThen` — `doc.at(0).andThen((j) => j.str("name"))`
— which reads better but pays one deep clone per hop. Both replaced the family
of fixed-shape accessors (`strAt`, `childI64At`, …) this module used to carry;
see docs/breaking-changes.md.

### `JsonNode`

```milo
pub struct JsonNode
```

kind: 0=null 1=bool 2=number 3=string 4=array 5=object

24 bytes, down from 56 with one named field per kind: the pool is the parse's
working set, and the wider node cost 10-15% of parse time in cache misses.
The two payload words mean something different per kind; only the jsonNode*
accessors and jsonNew* constructors below know the layout.
  null:          a = 0, b = 0
  bool:          a = 1 for true, 0 for false
  string:        a = strStart, b = strLen
  number:        a = index into the document's nums table, b = (strStart &lt;&lt; 32) | strLen
  array, object: a = childStart, b = (keyStart &lt;&lt; 32) | childCount (keyStart 0 for arrays)
The packed halves fit because jsonParse caps the input at 2^31-1 bytes and
the pool at 2^32-1 nodes: every count fits the low 32 bits, and every source
offset and key index (at most one per input byte) stays below 2^31, so the
high half never reaches the sign bit. That matters because `>>` on i64 is an
arithmetic shift: a high half of 2^31 or more would unpack negative.

Fields: `kind: i32`, `a: i64`, `b: i64`.

#### `jsonPretty`

```milo
pub fn jsonPretty(src: &string, indent: i64): string
```

Re-render a JSON document. `indent` > 0 indents nested values by that many
spaces per level, exactly as `JSON.stringify(v, null, indent)` does; `indent`
&lt;= 0 minifies, dropping every byte of whitespace outside a string.

Text that does not start with '{' or '[' comes back unchanged: a bare scalar
has nothing to indent, and text that is not JSON at all (a plain-text error
line, an empty body) is not this function's to mangle.
