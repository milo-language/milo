# std/event

The OS readiness poller behind the scheduler — kqueue on macOS, epoll on Linux, IOCP
on Windows — plus the non-blocking fd flag every one of them requires.

```milo
from "std/event" import { EventLoop, eventLoopClose, setNonblocking, eventRegisterRead, eventPoll }
```

This is the lowest layer of Milo's async I/O. `std/runtime` owns an `EventLoop` and
drives it for you, so importing this module means you are writing a primitive the
stdlib does not already provide — a poller over fds no std type wraps, or an
integration with a C library's own descriptor.

`std/event` is a platform split: `std/event.darwin.milo`, `std/event.linux.milo` and
`std/event.windows.milo` all export the same names and the resolver picks by target
OS. Write `from "std/event"`, never the suffixed path.

## Polling

Set an fd non-blocking before registering it. Registering one that still blocks is the
usual cause of a poller that reports ready and then hangs in `read`: readiness says a
byte *was* available, not that the next read will return.

`eventPoll` fills `readyFds`, a caller-allocated `[i32; N]` with `N >= maxEvents`
passed bare, and returns how many fds are ready, or -1 on error. A negative
`timeoutMs` blocks indefinitely.

```milo
let fd: i32 = 0                 // stdin, or any descriptor you own
var el = EventLoop.new()!
setNonblocking(fd)
eventRegisterRead(el, fd)

var ready: [i32; 8] = [0; 8]
let n = eventPoll(el, ready, 8, 1000)
eventLoopClose(el)
```

## Wakeups and embedding

`eventLoopInitWakeup` arms a self-pipe (or its platform equivalent) that breaks a
blocked `eventPoll` from elsewhere: that is how a `Promise.blocking` worker tells the
scheduler its result is ready. `eventLoopFd` and `eventLoopFromFd` hand Milo's poller
to another runtime, or wrap one that runtime already owns.

## API reference

`std/event` has one implementation per target (darwin, linux, windows); the resolver picks the one for the target you build for.

### `EventLoop`


A kqueue/epoll/IOCP poller handle. Create one with `EventLoop.new()`; release it with
`eventLoopClose`.

### Functions

#### `clearNonblocking`

```milo
pub fn clearNonblocking(fd: i32): i32
```

Clear O_NONBLOCK. fd 0/1/2 share an open file description with the parent
shell, so a non-blocking flag left set here leaks out and makes the shell's
reads return EAGAIN after we exit. Restore blocking mode before exiting.

Arm a wakeup that breaks a blocked `eventPoll` from elsewhere; this is how a

#### `eventPoll`

```milo
pub fn eventPoll(el: &EventLoop, readyFds: *i32, maxEvents: i32, timeoutMs: i32): i32 // darwin, linux
pub fn eventPoll(el: &EventLoop, readyFds: *i32, _maxEvents: i32, timeoutMs: i32): i32 // windows
```

poll for ready events. readyFds: caller-allocated *i32 array with capacity >= maxEvents.
returns count of ready fds, or -1 on error.
timeoutMs &lt; 0 means block indefinitely.

A fixed `[i32; N]` array passes bare: it coerces to `*i32`.
