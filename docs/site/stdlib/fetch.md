# std/fetch

The HTTP client and the TLS client socket. `fetch` resolves the host, speaks TLS for an
`https` URL and follows redirects. It is split out of [`std/net`](net) so a plain-TCP
program never links OpenSSL: importing `std/fetch` is what pulls it in.

```milo
from "std/fetch" import { fetch, fetchWith, fetchWithTimeout, FetchOptions, FetchTimeouts, FetchResponse }
```

## Example

```milo
let resp = fetch("https://example.com/")!
if resp.ok() {
    print(resp.text())
}
match resp.header("Content-Type") {
    Some(ct) => print(ct),
    None => {},
}

let opts = FetchOptions { method: "POST", headers: "Content-Type: text/plain", body: "hi" }
let posted = fetchWith("https://example.com/echo", opts)!
print(posted.status)
```

## Timeouts

`fetch` and `fetchWith` wait as long as the server takes, so one upstream that accepts
the connection and then goes quiet hangs the caller. `fetchWithTimeout` bounds the
connect (with its TLS handshake) and the whole request, redirects included, and answers
`NetError.Timeout(stage)` instead. `0` leaves either limit off. It works the same on a
green task and on a plain `main`.

```milo
let limits = FetchTimeouts { connectMs: 5000, totalMs: 20000 }
match fetchWithTimeout("https://example.com/feed.json", FetchOptions { method: "GET", headers: "", body: "" }, limits) {
    Ok(resp) => print(resp.status),
    Err(e) => print(e.message()),   // "timeout: response" when the server stalled
}
```

## Fetching a URL someone else chose

A server that fetches user-supplied URLs (link previews, webhooks) has to refuse
private addresses, and checking the address then calling `fetch` resolves the name
twice: a DNS answer that changes in between sends the request past the check.
`fetchAt` connects to an address you resolved and vetted yourself, keeps the URL's
host for the Host header and the TLS certificate check, follows no redirect, and
reads at most `maxBytes`. Vet and resolve each redirect hop the same way.

```milo skip
let ip = resolve(parseHost(url))?
if !isPublic(ip) { return Err("refused") }   // your own range check
let resp = fetchAt(ip, url, FetchOptions { method: "GET", headers: "", body: "" },
                   FetchTimeouts { connectMs: 5000, totalMs: 10000 }, 262144)?
```

### `FetchTimeouts`

```milo
pub struct FetchTimeouts
```

Limits on one fetch, in milliseconds; 0 means no limit. `connectMs` bounds each TCP
connect together with its TLS handshake; `totalMs` bounds the whole call from the
first connect to the last body byte, redirects included. DNS is not covered: a lookup
is bounded only by the system resolver's own timeout.

Separate from FetchOptions, not fields on it: struct literals are exhaustive, so a new
field would break every FetchOptions literal in every program that builds one.

Fields: `connectMs: i64`, `totalMs: i64`.

#### `TlsStream.fromTcp`

```milo
fn TlsStream.fromTcp(conn: TcpStream, hostname: &string, caFile: &string): Result<TlsStream, NetError>
```

Client handshake over an ALREADY-connected socket. This is the entry point a
protocol with in-band TLS negotiation needs — Postgres' SSLRequest, SMTP STARTTLS:
the socket must carry plaintext first, so TLS setup cannot own the connect() too.
The stream is consumed: the returned TlsStream owns its fd, and every error path
closes it, so nothing is left behind to use after the handshake.

#### `TlsStream.incoming`

```milo
fn TlsStream.incoming(self: TlsStream): Channel<string>
```

Stream decrypted inbound bytes as an iterable channel, pumped on a green
task — the uniform async-read API, TLS variant. Uses the SSL-aware read
(parks on WANT_READ) rather than the raw-fd fdChannel. `for chunk in
tls.incoming()`; the channel closes at EOF / on SSL error.
Consumes the stream, so send any request first. The detached pump reads
through the SSL state, so the pump has to own it: when incoming() only
borrowed, dropping the stream ran SSL_read on a freed SSL. The connection
closes when the pump ends (EOF, an SSL error, or the first chunk that
arrives after every receiver is gone).

#### `TlsStream.recv`

```milo
fn TlsStream.recv(self: &TlsStream): Result<string, NetError>
```

Read everything until the peer closes, as one string (blocks to EOF).
Prefer `incoming()` for streaming/incremental consumption.

#### `TlsStream.recvBy`


#### `TlsStream.recvOnce`

```milo
fn TlsStream.recvOnce(self: &TlsStream): string
```

A single SSL_read of whatever has arrived, unlike `recv()` which loops to EOF.
A server must answer a request while the client still holds the connection open,
so recv() would deadlock there; this returns after one record.

#### `TlsStream.recvUpTo`


caller that must not buffer whatever a hostile server chooses to send. The
result may run up to one TLS record past the cap.

#### `fetchAt`

```milo
pub fn fetchAt(ip: u32, url: &string, opts: FetchOptions, t: FetchTimeouts, maxBytes: i64): Result<FetchResponse, NetError>
```

One request for `url`, sent to the IPv4 address `ip` the caller already resolved
(std/net `resolve`), with no redirect followed: a 3xx comes back as is, Location
and all. The Host header and the TLS certificate name still come from `url`.

This is the primitive for fetching a URL someone else chose. Checking the host's
address and then calling `fetch` resolves the name twice, and a DNS answer that
changes in between (rebinding) sends the request somewhere the check never saw;
here the address checked is the address connected to. Each redirect hop is the
caller's to vet and resolve the same way.

At most `maxBytes` bytes of the response are read, headers included (0 for no
limit), and the response is parsed from what arrived, so a cut-off body comes back
short rather than as an error. `t` bounds the request as in fetchWithTimeout.

The authority for the Host header: the host, plus `:port` whenever the port is
