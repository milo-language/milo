# std/process

Command execution and child process management.

```milo
from "std/process" import { Process, run, capture }
```

`run` and `capture` go through the shell. `Process.spawn` starts a program by path with
no arguments. `Command` is the general form: arguments passed verbatim (no shell),
working directory, environment, and where each standard stream goes.

## Command

```milo
from "std/process" import { Command, Stdio }

let child = Command.new("git")
    .arg("status")
    .dir(repoPath)
    .env("GIT_PAGER", "cat")
    .stderr(Stdio.Pipe)
    .spawn()!
```

Pointing a direction-specific `Stdio` mode at the wrong stream is a `spawn` error naming
the stream, and no child is created: a redirection that cannot be honoured never lands
on your terminal instead.

## Command.env vs Env.set

`Command.env` changes one child's environment. `Env.set` (in `std/env`) changes *this*
process's environment, which every later child inherits. Prefer `Command.env` — it has no
thread-safety caveat and no effect on anything but the child you are starting.

## Example

```milo
from "std/process" import { Command, Process, Stdio, run, capture }

fn main(): i32 {
    // Run and get exit code
    let code = run("echo hello")!

    // Capture output
    let output = capture("uname -s")!
    print(output)

    // Spawn and wait
    let proc = Process.spawn("/usr/bin/true")!   // a program path: no arguments, no shell
    let exitCode = proc.wait()!

    // A child with its own cwd, environment and log file
    var child = Command.new("make")
        .arg("-j4")
        .dir("build")
        .env("CC", "clang")
        .stdout(Stdio.Write("build.log"))
        .stderr(Stdio.Merge)
        .spawn()!
    let status = child.wait()!
    child.close()

    return 0
}
```

## API reference

`std/process` has one implementation per target (default, windows); the resolver picks the one for the target you build for.

### `Child`

```milo
pub struct Child
```


Bidirectional pipe to a spawned process: parent writes the child's stdin and
reads its stdout/stderr. Built for stdio-framed protocols (DAP, LSP) where the
parent drives a long-lived adapter over its standard streams.

Reads are blocking. When mergeStderr is false the caller MUST drain both
stdout and stderr or the child can deadlock filling an unread pipe; DAP puts
protocol on stdout and logs on stderr, so mergeStderr=true is the safe default.

Fields:

- `pid: i32`
- `stdinFd: i32`: parent → child stdin
- `stdoutFd: i32`: child stdout → parent
- `stderrFd: i32`: child stderr → parent, or -1 when merged into stdout

### `Command`

```milo
pub struct Command
```

Builds a child process: program, arguments, working directory, environment, and where
each standard stream goes. Each method takes the builder and hands it back, so calls
chain; `spawn` borrows, so one Command can start several children.

The default is stdin and stdout on pipes with stderr merged into stdout. When stderr
is not merged, drain both streams, or the child can deadlock filling an unread pipe.

Fields:

- `program: string`
- `argv: Vec<string>`
- `workDir: string`: "" means "the parent's working directory", which is not a path a child can meaningfully be given, so there is no ambiguity with a real value.
- `envChanges: Vec<EnvChange>`
- `inheritEnv: bool`
- `inMode: Stdio`
- `outMode: Stdio`
- `errMode: Stdio`

### `Stdio`

```milo
pub enum Stdio
```

Where one of a child's standard streams comes from, or goes to.

Three of these are direction-specific and a spawn that mixes them up is a hard error
naming the stream, never a stream silently left on the parent's terminal.

Reading a stream that is not a pipe is a contract violation: `writeStdin`,
`readStdout` and `stdout()` require their fd, checked in debug builds.

Variants:

- `Pipe`: A pipe the parent holds the other end of: Child.writeStdin / stdout() / stderr().
- `Inherit`: The parent's own stream, unchanged — the child shares the terminal.
- `Null`: /dev/null (NUL on Windows).
- `Merge`: stderr only: whatever stdout was pointed at, so both arrive interleaved on one fd.
- `Read(string)`: stdin only: read the file at this path.
- `Write(string)`: stdout/stderr only: create or truncate the file at this path.
- `Append(string)`: stdout/stderr only: create or append to the file at this path.
