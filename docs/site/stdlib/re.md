# Regular Expressions, JavaScript syntax (`std/re`)

```milo
from "std/re" import { Re, ReMatch }
```

`Re` compiles a pattern written the way JavaScript writes it (the text between the
slashes of `/.../flags`) and matches it in pure Milo: no libc, the same behavior on
every platform, and a compiled `Re` is plain data any task or thread can share. It
supports classes and `\d \w \s \b`, groups, named groups, lookahead and lookbehind,
backreferences, lazy quantifiers, and the `i`, `m` and `s` flags. Matching is by
codepoint, so `.` and `[é-ü]` see whole characters.

Use `std/regex` only when you need POSIX semantics; for patterns ported from
JavaScript, or anything with lookaround, use this module.

## Example

```milo
from "std/re" import { Re }

fn main() {
    let bot = Re.new("(?<! cu)bots?(?:\\b|_)|crawl|spider", "i")!
    print(bot.test("Mozilla/5.0 (compatible; Googlebot/2.1)"))   // true

    let date = Re.new("(?<y>\\d{4})-(?<m>\\d{2})", "")!
    let m = date.find("released 2026-10")!
    print(m.named("y") ?? "")                                     // 2026
    print(date.replaceAll("2026-10 and 2025-01", "$<m>/$<y>"))    // 10/2026 and 01/2025
}
```

The matcher backtracks, as JavaScript's does, but over an explicit stack (input
length never deepens the call stack) and under a step budget proportional to the
input. A pathological pattern on hostile input, such as `(a+)+$` against `"aaaa…b"`,
reports no match in bounded time instead of hanging. `testBounded` tells "no match"
apart from "gave up".

## API reference

### `Re`

```milo
pub struct Re
```

A compiled pattern. Plain data: share it freely.

Fields:

- `prog: Vec<ReInst>`
- `classes: Vec<ReClass>`
- `groups: i64`
- `names: Vec<string>`
- `nameGroups: Vec<i64>`
- `slotCount: i64`: Loop-progress registers live after the capture slots.
- `icase: bool`
- `multiline: bool`
- `dotAll: bool`
- `source: string`
- `firsts: Vec<ReFirst>`: Which bytes can begin a match (firsts[0]) or a branch, so the scan skips start positions and alternatives that cannot.
- `splitFirst: Vec<i64>`: Per instruction: for a SPLIT, the index in `firsts` of its preferred branch's filter, or -1 (no filter); -1 for every other instruction.

#### `Re.firstFrom`


Walk the zero-width edges from `start` and collect what the first consumed
codepoint can be. Assertions (^ $ \b lookaround) do not consume, so they are
stepped over: they only narrow where a match starts, never widen it, which keeps
the set a superset of the truth (a filter, never a verdict).

#### `Re.run`

```milo
fn Re.run(self: &Re, vm: &mut ReVm, s: &string, startPc: i64, startSp: i64, mustEnd: i64): i64
```

Run from `pc` at `sp` until MATCH (or, for a lookaround body, LOOKEND). Returns the
end position, or -1. `mustEnd` >= 0 requires the body to end exactly there (a
lookbehind tried from an earlier start). Slot writes made on the way to a success
stay; on failure every write is undone back to the barrier this call pushed.
